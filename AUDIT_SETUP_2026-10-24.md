# Setup audit 2026-10-24: bugs and inefficiencies

Four parallel Opus audit passes over the setup surface - the engine (`src/lib/engine/instrument.ts`), the checker stack (`battery_checks.ts`, `stage_structure.ts`, brand-mention modules), the wizard client (`grid_setup.tsx`, `setup_wizard.tsx`), and the API routes + create/edit-setup persistence - each consolidated and the top findings re-verified by hand against the code. Read-only: nothing edited, no model calls, no prod writes. The checker findings were additionally confirmed by zero-spend probe scripts importing only `battery_checks.ts` (no DB URL, no API keys).

Severity: S1 = security, data loss, or measurement shipped unchecked; S2 = real bug with a plausible trigger; S3 = inefficiency / hygiene. Findings marked **[verified]** were re-confirmed by hand in this session; the rest were code-traced (and for the checker layer, probe-executed) by the audit pass that found them.

## S1

**1. Share-link viewers pass auth on every setup route and on project create. [verified]**
`src/lib/auth.ts:83-91` returns `{userId: "share", shareProjectId}` for a valid `ap_share_token` cookie; `requireAuth` (:256) and `requireAuthOrDemo` (:270) accept any non-null auth. Only `requireProject` scopes a share context, and no setup route, `POST /api/projects`, or `/api/drafts` calls it. Consequences: a share-link holder can call `/api/setup/grid/*` directly and run uncapped paid generation (middleware covers `/app`/`/projects`/`/admin`, not `/api`); can create trackers (`getPlanFor` returns `"enterprise"` for share contexts at auth.ts:162, so no tracker limit; `user_id = "share"` inserts fine); and all share viewers share the `"share"` user, so they list each other's trackers and drafts. Fix shape: reject `shareProjectId` contexts in `requireAuth`/`requireAuthOrDemo`, or add a `requireMember()` on every route that writes or spends.

**2. Battery passes stamp PROVISIONAL units as terminal - unchecked seeds freeze as checked. [verified]**
`instrument.ts:4689` (deadline-cut units land in `resolved[u]` and `provisionalOut`), `:5531` (taken-over units same), `:4927-4931` (`stampPassed` rewrites `{cells, rules, passed}`, erasing the provisional marker), `:5557-5566` (the passes gate checks only that units are resolved, never `provisionalOut`). Scenario: a design heal is cut at the 190s heal deadline (or the design checker outages to `unchecked`); the unit is written provisional; the passes run before 235s and stamp it; the route answers "retry"; on retry the unit reads `rules === r28` and serves as finished. The design layer never ran on it and the terminal `seedFlags` verdict was skipped too. This reopens the 2026-10-02 review's unchecked!=checked hole through a new path. Companion bug: the passes also stamp units whose labeler reply was unusable (count mismatch or double parse failure at :4980, :5128→5219, :5263→5345) - `stampPassed` runs regardless, so 5 job labels for 6 use-case cells permanently marks all 6 judged.

**3. Blurring a scenario label wipes every engine-written cell, hand edits and paraphrase sets included. [verified]**
`grid_setup.tsx:2365-2368`: the label input's `onBlur` calls `onRecompose(...)` whenever the row is ticked - even when nothing changed. The recompose keeps only `.custom` cells (`grid_setup.tsx:886`) and resets to the compose step. By the time the 2026-10-07 "keep the user's version" merge in `writeCells` (:1251-1262) runs, `a.state.cells` holds only custom cells, so there is nothing to merge: every seed edit, redraw, and reviewed paraphrase set is gone and the user redoes coverage → cells → paraphrases. Same trigger from a tick change, journey toggle, near neighbor, reword, base-pill change, or Reset to suggested after the user has been to Prompts.

**4. Multi-word brand-name parts count as DEFINITE mentions even when they are everyday/category words. [probe-confirmed]**
`battery_checks.ts:511-514`: a 3+-word name mints every contiguous 2+-word run as a definite form, guarded only by "contains one 3+-letter word" - never checked against category vocabulary or the everyday-word list, never sent to the judge. "U.S. Bank" → `s bank`; "Bank of America" → `bank of`. Probe-confirmed through `checkPromptAgainstSpec`: a blind AmEx seed saying "My partner's bank keeps pushing a card..." flags `blind_names_brand` U.S. Bank; "my bank of choice" names Bank of America. With a label like "Chase Credit Cards", every blind AmEx text saying "credit cards" names Chase. The r15 fix covered only the `u s` shape. Fix shape: a part must carry a word that is neither common nor category vocabulary, else route to the judge like a single ambiguous word.

## S2 - engine (instrument.ts)

- **Problem-recognition pass silently skipped at the deadline** (:5234): the concern and use-case passes set `passesCut = true` past `deadlineAt`; the PR pass has no matching line. If the use-case pass finishes after 235s, the PR pass never runs and `coalesced` still writes the `"1"` completion marker.
- **`passesKey` lacks `SEED_RULES_VERSION`** (:4918, upgrade write :5463): on an r-bump, mechanically passing units are rewritten without `passed` but the old completion marker survives - if no unit fails, the new rules' battery passes never run; if any unit fails, `mine > 0` invalidates the marker and EVERY cell re-judges (the re-roll the 2026-10-07 change was meant to stop).
- **Design-intent changes in r-bumps never reach cached cells** (:5443-5467): the serve-time re-judge runs `seedRule` (mechanical) only; `stageDesignIntent`/`checkDesignFidelity` run only at generation. r16/r17/r22/r24/r26/r27/r28 all changed design intents; a cached premium_worth seed with no pick invitation upgrades in place and serves clean under r28. AGENTS.md's "the r26 re-judge regenerates the cells the new intents fail" describes behavior the code does not have.
- **Two requests that split a battery both run the passes** (:5559-5561): each request with `mine.length > 0` writes `{__pending: 0}` to `passesKey` unconditionally, so request A can overwrite request B's live claim and both run the labeler + heals on the same cells; last write wins, responses can carry different texts for one cell.
- **A failed stakes judgment grants the journey override and caches it ~183 days** (:1148-1151 inside the `coalesced` read at :982): any Anthropic error grants every claimed deviation, cached under the shared category key - one transient error reinstates the "hosting makes a habitual market considered" override journeys25-28 exist to stop.
- **Phrasings claim is a plain `cacheSet`, not CAS** (:7022): two requests that both read a miss both pay the full writer + retries + structure chain for the same cells. The grid path and `coalesced` moved to `cacheClaim` for exactly this race. (Found independently by two passes.)
